🧪 共聚物热导率项目 · 里程碑作战地图

基于主动学习的双组分共聚物序列–热导率粗粒化模拟与设计
4 人 · 0 基础 12 周（2026.08.03 – 10.25） 目标：跑通「模拟→预测→推荐→验证」闭环，输出设计规则

0. 项目是什么

用 粗粒化分子动力学（LAMMPS） 模拟 AB 共聚物，用 RNEMD 算热导率 κ；把序列编码成特征，喂给 高斯过程回归（GPR）；再用 期望改进（EI） 主动推荐新序列去模拟——用约 20 次模拟替代百万级穷举，最后提取「序列→构象→κ」定量设计规则。

① 序列→特征编码→ ② GPR 预测 κ→ ③ EI 推荐新序列→ ④ 模拟验证→ ⑤ 再训练→ ⑥ 循环收敛 → 设计规则
📌 里程碑不是流程里的步骤，而是这条环路「转到什么程度」的三个检查点： M1＝环路的一端（模拟验证）对单序列跑通；M2＝左半边（数据+模型）跑通；M3＝整条环转起来。

1. 怎么一起干活（不割裂的分工法）

原则：每个里程碑的所有环节，4 个人一起做。不再"一人一块地"，而是每个环节里 4 人各担一个角色，角色随环节轮换：

🛠 主攻 Lead
该环节的技术负责人，负责把东西做出来。轮换着当——每个环节的主攻换人。
🤝 辅助 Support
配合主攻分担具体活：写脚本、跑数据、查资料。主攻卡住时一起 debug。
🔍 质检 Reviewer
第二双眼睛：检查产出对不对、挑错、提问。0 基础团队最缺的就是"有人检查"。
📝 记录 Scribe
记录参数、过程、踩坑，产出环节笔记，并向全队复述——保证知识不留在一个人脑子里。
💡 为什么这样不割裂：① 每个环节 4 人都有活；② 主攻/质检天然形成"做的人 + 查的人"，错误当场暴露；③ 记录环节保证每周例会人人能讲清楚；④ 角色轮换 = 每个人都碰过全流程，中期检查谁都能上台讲。

2. 里程碑 M1 · 单序列全流程跑通

🎯 M1：一个交替序列走完「建模→平衡→RNEMD→构象分析」，κ 与文献量级对齐

时间：W2–W4（08.10 – 08.30）｜这是全项目最关键的坎，后面所有工作都建立在它上面
环节 1建模：序列 → data/in 文件
把序列字符串"ABABAB…"变成 LAMMPS 能读的输入文件：A/B 两种珠子、FENE 键（K=30, R0=1.5）、LJ 非键（ε=1.0, σ=1.0, 截断 2.5, 排除 1-2/1-3）、周期盒子。
🛠 主攻 A最懂 LAMMPS 输入格式，写 data + in 脚本
🤝 辅助 B写"序列字符串→data 文件"生成脚本，和 A 一起逐段核对
🔍 质检 C逐行检查 data 文件（键有没有连错、珠子类型对不对），用 VMD 可视化看模型长什么样
📝 记录 D产出《珠簧模型参数说明》一页纸：每个参数什么意思、从哪来的
✅ 产出：交替序列 data+in 文件 + 参数说明一页纸
环节 2平衡：单链跑通 → 多链周期盒 NVT 平衡
先单链 20 珠验证模型没错；再扩成 50–100 链 × 20 珠周期盒子做 NVT 平衡，直到能量、密度不再漂移。多链是必须的：热导率是材料性质，单链边界效应太大，且链间范德华本身是热流通道。
🛠 主攻 A调 LAMMPS 跑平衡，判断收敛
🤝 辅助 B写收敛检查脚本（能量/密度随时间曲线，自动判稳）
🔍 质检 C看收敛曲线 + VMD 检查平衡后构型是否合理（有没有珠子重叠、盒子有没有撑爆）
📝 记录 D记录平衡条件（时长/步长/温度），产出《平衡日志模板》
✅ 产出：平衡轨迹 + 收敛证据（能量/密度曲线）
环节 3RNEMD 施加热流
实现 Müller-Plathe 方法（LAMMPS fix thermal/conductivity）：盒子沿 z 分层，反复交换最热/最冷层的动能 → 产生稳定热流 J。关键：温度梯度 dT/dz 要变成线性且稳定才算收敛。
🛠 主攻 A实现 fix，调热流大小与模拟时长
🤝 辅助 B写监控脚本：实时输出每层温度，看梯度是否线性
🔍 质检 C画温度剖面图，判定线性区在哪、边界效应多大
📝 记录 D记录调参过程（试了哪些参数、什么表现），产出《RNEMD 调参记录》
✅ 产出：稳定的温度梯度 + 热流 J
⚠️ 主要风险点：RNEMD 不收敛 → 加大热流、延长模拟、增大盒子（预案见规划 §6）
环节 4算 κ
用稳定后的 J 和 dT/dz 代入 κ = J / (2A·dT/dz)。A 是盒子横截面积；那个 2 是几何因子（热流同时往两个方向走）——最常见错误就是漏掉它。
🛠 主攻 A主导计算，给出 κ 数值
🤝 辅助 B写自动计算脚本（读 log → 出 κ）
🔍 质检 C复核公式：几何因子 2、横截面积 A 的量纲对不对
📝 记录 D写《κ 计算与单位换算笔记》：real→W/m·K 每一步怎么换
✅ 产出：κ 数值（LAMMPS real 单位）
环节 5单位换算 + 文献校准（M1 验收官）
把 κ 换成 W/m·K，与文献中粗粒化高分子的 κ 量级对比（高分子通常 0.1–0.5 W/m·K）。对得上 = 方法正确；差几个数量级 = 前面某步错了。
🛠 主攻 D查文献 κ 量级，做对比表（主攻轮换示例：这个环节换 D 当主攻）
🤝 辅助 A提供换算细节（LAMMPS real 单位制参数）
🔍 质检 B复核换算公式每一步
📝 记录 C画对比图：模拟 κ vs 文献 κ
✅ 产出：κ（W/m·K）+ 文献对比图 ← M1 验收核心证据
⚠️ 风险点：单位换算错、几何因子 2 漏掉 → 数值差好几倍/数量级
环节 6构象分析
用平衡轨迹算三个构象量：Rg 回转半径（链团多大）、末端距（链多舒展）、取向序 P2（链多整齐）。M1 阶段只要求"能算出来"，为 M2 特征工程铺路。
🛠 主攻 C写 Rg/末端距/P2 脚本（MDAnalysis/mdtraj）
🤝 辅助 A提供轨迹，解释这三个量的物理含义
🔍 质检 D检查数值合理性，并思考：这些量以后怎么当 GPR 特征？
📝 记录 B把构象数据整理成表
✅ 产出：三个构象量的数值 + 初步图表
环节 7重复 3 次 + 汇总验收
同一条件重跑 ≥3 次，κ 取平均±误差（单次模拟有统计涨落）。汇总成 M1 验收数据表。
🛠 主攻 B排队跑 3 次重复（复用环节 1 的生成器）
🤝 辅助 A检查每次算例质量（温度梯度图都正常吗）
🔍 质检 C画 κ 误差棒图
📝 记录 D汇总《M1 验收数据表》：序列、κ、κ_err、构象量、文献对比
✅ 产出：κ ± 误差 + M1 验收数据表 → 里程碑 M1 达成 🎉
🔄 角色轮换轨迹：环节1–4 主攻 A → 环节5 主攻 D → 环节6 主攻 C → 环节7 主攻 B。每个人既当过主攻，也当过质检/记录。

3. 里程碑 M2 · 初始数据集 + 统一数据管线

🎯 M2：把单序列流水线升级成"一条命令批量跑 5 个序列"，CSV 规范定死，GPR 首训

时间：W5–W6（08.31 – 09.13）｜9 月中旬中期检查（约 09.15）展示内容 = M1 + M2，无缓冲
环节 1序列生成器 + in 模板（批量化的地基）
B 的生成器升级为支持任意序列（交替/嵌段/无规），A 的 in 脚本模板化——改序列字符串就能出整套输入文件。
🛠 主攻 B生成器 v2 + in 模板
🤝 辅助 A提供模板规范，用交替序列试跑验证
🔍 质检 C随机抽 3 个序列核对生成的 data 文件（键、盒子、类型）
📝 记录 D写生成器使用说明（怎么加一个新序列）
✅ 产出：一键生成任意序列输入文件
环节 2批量跑 3 类代表序列
交替/嵌段/无规各 2–3 个代表序列，用 M1 定好的参数批量跑，检查每个算例的收敛质量。
🛠 主攻 A定首批序列清单，检查收敛质量
🤝 辅助 B批量管理器 v1：序列清单→逐个跑→收集→汇总，带失败重试
🔍 质检 C抽查温度梯度图、能量曲线，标记可疑算例
📝 记录 D记录每序列的参数与耗时（为 W9 挂机估算算力）
✅ 产出：3 类序列首批 κ 数据
环节 3批处理构象分析
M1 的构象脚本升级成批处理：自动遍历轨迹 → 构象汇总 CSV。
🛠 主攻 C批处理脚本（遍历轨迹→CSV）
🤝 辅助 B规范轨迹文件命名，方便脚本遍历
🔍 质检 D用已知序列核对构象数值合理性
📝 记录 A记录每序列轨迹产出情况
✅ 产出：构象汇总 CSV（Rg/末端距/P2 列）
环节 4特征编码器（D 的主场）
序列字符串 → 特征向量：交替度、嵌段长度均值/最大/方差、最长嵌段、A–B 邻接数。与 B 的序列格式严格对齐。
🛠 主攻 D实现编码器 + 测试样例（用 W3 的雏形正式化）
🤝 辅助 B对齐序列字符串格式（编码器与生成器共用同一套）
🔍 质检 C手算 2 个序列的特征值，和编码器输出对账
📝 记录 A记录特征定义与来源（为什么选这些特征）
✅ 产出：特征编码器 + 特征矩阵 X
环节 5CSV 定稿 + 误差分析（全队接口，最重要）
统一 10 列规范：sequence, alt_degree, block_mean, block_max, block_var, Rg, end_to_end, orient_p2, kappa, kappa_err。误差 = 重复标准差或块平均。这是全队不互相等数据的关键，中期检查评审的就是它。
🛠 主攻 B/CB 汇总 CSV 定稿+入库规范；C 做误差分析（块平均/重复标准差）
🤝 辅助 A确保 5 个序列数据质量（收敛检查、重复完整性）
🔍 质检 D用数据加载函数试读 CSV，检查列名/单位/缺失值
📝 记录 全员W6 例会评审最终 CSV 规范，人人签字确认
✅ 产出：定稿 CSV + 误差分析 + 「构象-序列」初步图表
环节 6GPR 首次训练（M2 验收之一）
用 5 个样本训练第一版 GPR：StandardScaler 标准化 → LeaveOneOut 交叉验证 → 预测 vs 真实图，RBF/Matern 核对比。5 个样本必然过拟合，这一步的意义是"验证数据管线畅通 + 全员看懂 GPR 是什么"。
🛠 主攻 D训练 + 评估图（这是 D 从 W1 就开始铺垫的主场）
🤝 辅助 C画预测 vs 真实图、误差图
🔍 质检 B检查数据是否泄漏（scaler 是否只 fit 训练集）
📝 记录 A记录 GPR 概念笔记：核函数、后验均值/方差、交叉验证是什么
✅ 产出：GPR 评估图（LOO 预测 vs 真实）→ 里程碑 M2 达成 🎉（接着中期检查）

4. 里程碑 M3 · 主动学习闭环跑通

🎯 M3：D 推荐 → B 自动模拟 → C 分析 → D 重训，闭环迭代 10 轮；国庆挂机到 20 次并收敛

时间：W7–W9（09.14 – 10.04）｜验收：≥20 次模拟且连续两轮 κ 提升 <5%
环节 1EI 采集函数（把"预测"变成"推荐"的关键）
实现期望改进 EI = E[max(f(x)−f_best, 0)]，用 GPR 的后验均值+方差算"哪个序列最值得模拟"。这是主动学习和普通回归的唯一区别。
🛠 主攻 D实现 EI（scipy.stats.norm）+ 单元测试
🤝 辅助 C画出"后验均值±方差 + EI 曲线"示意图（W7 例会 D 讲 EI 原理时用）
🔍 质检 B用 2 个已知结果反推验证 EI 打分合理
📝 记录 A记录 EI 公式推导笔记，例会负责复述
✅ 产出：EI 推荐器 + 原理讲解图
环节 2任务队列 v1（B 的主场）
队列脚本：读 D 的推荐文件 → 只跑新序列 → 结果自动追加数据集。这是"闭环能自动转"的机械部分。
🛠 主攻 B队列脚本 v1（推荐文件→模拟→追加 CSV）
🤝 辅助 A提供算例质量检查接口（每跑完一个自动校验）
🔍 质检 C模拟一次完整队列流程，确认数据正确追加
📝 记录 D写《队列脚本使用说明》
✅ 产出：自动追加数据的队列脚本
环节 3热流分解初版（加分项，不阻塞主线）
用 compute heat/flux 区分键内（bond）与范德华（pair）贡献，对比占比随序列变化。定位是"尽力而为的加分项"。
🛠 主攻 C热流分解实现初版（W4 报告落地）
🤝 辅助 A提供 per-atom 热流输出配置
🔍 质检 D检查分解数值是否自洽（各贡献之和 ≈ 总 κ）
📝 记录 B记录分解方法笔记
✅ 产出：bond vs pair 贡献占比初版
环节 4闭环串联：四人的手全在这条环上
把已有部件接成闭环：读数据→训练 GPR→EI 推荐 top-2→写推荐文件→B 跑模拟→读新数据→重训。每个环节一个人守着。
🛠 主攻 D主循环脚本 + 全程日志
🤝 辅助 B守队列端：模拟→数据回流
🤝 辅助 A守质量端：新算例收敛检查
🔍 质检 C守分析端：随跑出图，发现异常立即喊停
✅ 产出：闭环 v1（W8 例会上全员过一遍流程图，D 主讲）
环节 5迭代 10 轮 + 收敛判据
闭环跑 10 轮迭代；实现收敛判据（连续两轮最佳 κ 提升 <5% 即停）。加容错：某序列模拟失败要跳过而不是卡死。
🛠 主攻 D收敛判据实现 + 10 轮数据记录
🤝 辅助 B队列容错（失败重试/跳过）+ 日志
🔍 质检 C每轮出 κ vs 轮次图（草稿），检查模型是否"越选越准"
📝 记录 A记录每轮推荐了哪些序列、结果如何
✅ 产出：10 轮迭代 + 迭代曲线草稿 → 里程碑 M3 达成 🎉
环节 6国庆挂机迭代至 20 次（W9）
节前把队列排好挂机跑（10.1–10.7 弹性），节后收数据、检查收敛状态、输出最终迭代曲线。这是全项目算力利用率的关键周——W8 必须把队列跑顺。
🛠 主攻 B挂机脚本最终检查（断点续跑/错误重启），节后收数汇总
🤝 辅助 A算例质量抽检
🔍 质检 C节后补随跑分析图
📝 记录 D节前写好自动迭代脚本；节后输出迭代曲线（κ vs 轮次）
✅ 产出：20 次模拟 + 收敛判定 + 迭代曲线（主动学习价值的核心证据）

5. M3 之后（W10–W12）

  • W10 随机对照验证：随机序列 10–20 条对照组，检验最优 vs 随机 κ 提升 >20%（t 检验）

6. 怎么让 4 个人都能看到这个网站（5 分钟部署）

方法 A：GitHub Pages（推荐，免费、永久、不用命令行）

  1. 任意一人注册 GitHub（github.com，免费）
  2. 点右上角 + → New repository，名字随便如 project-site，选 Public，勾选 Add a README file，Create
  3. 进入仓库 → Add file → Upload files → 把本网页拖进去（重命名为 index.html）→ Commit changes
  4. 仓库 Settings → Pages → Source 选 Deploy from a branch → Branch 选 main → Save
  5. 等 1 分钟，访问 https://你的用户名.github.io/project-site/，把链接发群里即可

方法 B：本地先看——直接双击打开本 HTML 文件，浏览器就能看、能打勾（打勾状态存在自己浏览器里，部署后各人各自记）。

方法 C：不想建站——把各里程碑环节表格复制进飞书文档/腾讯文档（你们已用它做共享文档），同样能 4 人共同编辑打勾。

📌 进度打勾只存在你当前浏览器里（localStorage），4 个人各自打勾、周五例会时对着屏幕对一遍即可。
